# v0.1.1 Product Taxonomy

> Historical note: this document records the Phase 14 / `v0.1.1` product taxonomy. It is not current-facing `v0.1.2` guidance. Use `docs/project-summary.md`, `docs/release/v0.1.2-release-notes.md`, and `docs/testing/manual-v0.1.2-results.md` for the active Phase 15 release state.

MenuBarDeclutter `v0.1.1` should be understandable as:

> Hide clutter. Arrange icons safely. Find hidden icons. Recover if something goes wrong.

This taxonomy was the shared vocabulary for Settings, onboarding, status menu, support docs, feature docs, and release copy in the `v0.1.1` line.

## Top-Level Product Areas

| Area | Purpose | Belongs Here |
| --- | --- | --- |
| General | Basic app setup and app identity. | App startup, Launch at Login, onboarding reset, app version, app mode. |
| Hide & Reveal | The stable hiding workflow. | Expand, collapse, reveal all, auto-rehide, hover reveal, always-hidden zone, Basic hotkey, status menu behavior. |
| Arrange | Safe placement and placement help. | Command-drag guide, control item placement, separator placement, placement test, Placement Planner, Assisted Move. |
| Find & Rescue | Ways to locate, inspect, and recover hidden items. | Find Icon, Second Bar, crowded reveal fallback, New Item Inbox, lightweight groups/tags used inside item-finding workflows. |
| Privacy | Permission boundaries and local data handling. | Basic Mode boundary, Pro Mode boundary, diagnostics redaction, local support data, permission-required degraded states. |
| Recovery | Repair paths when layout or state is confusing. | Safe Mode, reset layout, reset settings, repair actions, diagnostics export, health report, crash marker recovery. |
| Advanced | Power-user, Preview, Labs, Experimental, and internal surfaces. | Profiles, Smart Triggers, Dynamic Hotkeys, Private Access, App Intents, URL automation, Import / Export, Spacing Labs, dogfood/internal tools, experimental settings. |

## Feature Status Vocabulary

| Status | Meaning |
| --- | --- |
| Stable | Supported in the `v0.1.1` product core when documented requirements are met. |
| Preview | Available for local testing with conservative gates and fail-closed behavior. |
| Labs | Explicit opt-in area for experiments that may affect system-level behavior. |
| Experimental | Explicitly enabled or confirmed actions that may fail depending on macOS state. |
| Deferred | Documented outside the supported `v0.1.1` scope. |
| Internal | Dogfood, developer, QA, or diagnostics-only behavior that is not normal product surface. |

Use `Disabled` and `Unavailable` as state labels inside UI when a feature is off or requirements are missing. Do not use them as product maturity statuses.

## Copy Rules

- Use `v0.1.1` language only when referring to historical `v0.1.1` docs.
- Describe Guided Manual Arrange as the stable icon placement path.
- Describe Placement Planner as Preview and non-mutating.
- Describe Assisted Move as Experimental, single-item, confirmed, and failure-prone.
- Keep Find Icon, Second Bar, New Item Inbox, crowded fallback, and lightweight groups inside Find & Rescue rather than separate product pillars.
- Keep Profiles, Smart Triggers, Dynamic Hotkeys, Private Access, automation, migration, Spacing Labs, and internal tools under Advanced.
- Do not describe fully automated icon moving, bulk moving, broad third-party activation, spacing mutation, or competitor migration as stable.
